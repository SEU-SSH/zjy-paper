## 1. Two-Scope Design of RQ3 (Read Carefully to Keep Claims 100% Accurate)

As already visualized with the vertical dashed separator in `figures/eval-ablation.pdf`, RQ3 evaluates five ablated variants organized into **two clearly bounded experimental scopes**:

- **Scope A — Full-Campaign Offline Specification & Oracle Ablations (`921` Invariants × `4` ISAs, `GCC 16.2` + `LLVM 23.1`)**:
  1. **`Full DeFenzz` (`Check IR` + `Hybrid RAG`)**
  2. **`w/o Formal Check IR` (`Raw Go Scripts`)** — replaces Step-3 declarative `Check IR` + deterministic ISA lowering + Z3 sanity checking with unconstrained LLM-written Go disassembly/sandbox checker scripts.
  3. **`w/o Hybrid RAG` (`Segmented CoT Only`)** — disables Step-1 cross-mechanism BM25+dense hybrid retrieval transfer, keeping only per-slice Segmented CoT extraction.
- **Scope B — Controlled End-to-End Online Audit Lane (`41` Invariants on `GCC 16.2.0` `AArch64`, `demo-workset` Pilot Benchmark)**:
  - Why a controlled 41-invariant subset? Running unconstrained `llm-judge` adjudication (`w/o Programmatic Oracle`) or unmapped whole-tree exploration (`w/o Source Mapping`) across all `921 × 4` ISA lanes would exceed several billion tokens (`llm-judge` alone already consumes `206.01M` tokens and `15.5h` cumulative LLM latency on just `41` invariants!).
  - Variants evaluated on the identical 41-invariant `GCC 16.2.0` `AArch64` slice:
    4. **`Full DeFenzz` (`41-Invariant Baseline`)** (`source_mapping=on`, `oracle=deterministic-checker`, `41` workers)
    5. **`w/o Source Mapping` (`inv-only`)** (`source_mapping=off`, `oracle=off`, `41` workers given the 41 invariants + raw GCC tree)
    6. **`w/o Programmatic Oracle` (`llm-judge`)** (`source_mapping=on`, `oracle=llm-judge`, `41` workers where an LLM adjudicates binary assembly/runtime outputs instead of `Check IR`)
    7. **`Bare Agent` (`free-agent`)** (`invariants=0`, `source_mapping=off`, `oracle=off`, `1` unconstrained security-auditing agent over the GCC tree)

### Exact Technical Explanation of Each Scope B Variant (Reviewer-Proof Prose Material)
1. **Why `0` True Bugs on `demo-workset` Is Actually a Strong Precision Result**:
   - The frozen 41-invariant `GCC 16.2.0` `AArch64` `demo-workset` slice happened to cover compiler paths whose BTI/SSP/MTE behaviors (e.g., `.aeabi_attribute Tag_Feature_BTI` emission when `HAVE_AS_AEABI_BUILD_ATTRIBUTES=1`) are valid ABI implementations rather than bugs.
   - On this tricky negative-control slice, **`Full DeFenzz`'s deterministic oracle cleanly rejected 100% (`4 / 4`) of candidate alerts with `0` leaked false positives** in `8,118.5s` LLM latency.
2. **`w/o Source Mapping` (`inv-only`)**:
   - Without Step-2 `Pass -> Function -> Branch` localization and compile-time `DEFENZZ_LOG` feedback, the 41 workers wandered across unrelated frontend/driver files, generating **`9` noisy speculative candidates** (`8` rejected + `1` leaked false claim `CAND-2025-001` with `poc_verified=False`, which mistook `-fstack-protector-explicit`'s documented opt-in semantics for a bug).
   - *(Note in `figures/eval-ablation.pdf`: the crimson bar `8` plots the `8` rejected false alerts; if including the `1` unexecutable `poc_verified=False` claim, all `9/9` candidates are false alerts.)*
3. **`w/o Programmatic Oracle` (`llm-judge`) — Direct Proof Against LLM Bug Adjudication**:
   - Replacing deterministic `Check IR` checkers with an `llm-judge` caused **three severe pathologies**:
     1. **Call & Latency Blowup**: LLM calls jumped **`2.31×`** (`1,160` $\to$ `2,681`), reasoning tokens jumped **`9.61×`** (`0.75M` $\to$ `7.25M`), and cumulative LLM latency exploded **`6.87×`** (`8,118.5s` $\to$ `55,787.7s`).
     2. **Hallucination Leak**: Out of `6` speculative candidates (`5` rejected), `llm-judge` "verified" `CAND-2026-002` (`poc_verified=False`), hallucinating a `-fsanitize=memtag-stack` link-spec omission purely from reading spec strings without executing a binary check.
     3. **Zero Confirmed True Bugs (`0`)**.
4. **`Bare Agent` (`free-agent`)**:
   - Given no security invariants, no source map, and no oracle, the unconstrained agent drifted out of security defenses entirely, filing a single uncompiled static claim (`poc_verified=False`, rejected) on GCC's `-muser-provided-CPU` JSON tuning parser (`0` defense bugs).
