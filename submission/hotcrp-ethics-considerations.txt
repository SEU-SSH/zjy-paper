This study involves no human subjects, user data, or interaction with third-party live systems, so no IRB review was required. We built GCC and LLVM from public source releases and ran all synthesized test programs inside isolated containers on our own server.

Following both projects' official reporting procedures, we reported all 111 silent defense bugs (58 in GCC and 53 in LLVM) to upstream maintainers before submission through GCC Bugzilla and LLVM GitHub Issues. The authors verified each report and included only a minimal C or C++ reproducer, compiler flags, and root-cause analysis. Maintainers have already confirmed 30 bugs (18 GCC, 12 LLVM) and fixed 11 in mainline (9 GCC, 2 LLVM), with several fixes backported to release branches. Maintainers also tagged 5 reports as wrong-code or miscompilation, while the remaining 76 submitted reports await triage or patch review. We continue working with maintainers on open tickets, and we omit bug numbers and CVE identifiers from the submission to preserve double-blind anonymity.

DeFenzz is a defensive compiler testing tool, and this paper introduces no new attack techniques. While our findings expose compiler patterns that silently weaken mitigations, exploiting them still requires a separate vulnerability in a target application. Reporting all bugs upstream before submission and releasing minimal compiler test cases instead of exploit code keeps misuse risk low. Silent defense bugs leave hardened software unprotected without warning, so finding and fixing them in GCC and LLVM brings clear security benefits that outweigh this residual risk.
